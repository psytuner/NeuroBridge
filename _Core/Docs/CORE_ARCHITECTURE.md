# [CORE_ARCHITECTURE] УСТРОЙСТВО ЯДРА NEUROBRIDGE И МУЛЬТИПРОЕКТНОГО КОНВЕЙЕРА
## 1. СТРУКТУРА СРЕДЫ C:\NEUROBRIDGE (100% ПОРТАТИВНАЯ)
- Корень `C:\NeuroBridge\`: `README.md` (инструкция), `старт_нового_чата.txt` (автоснимок памяти), `NeuroBridge_отчёт.txt` (отчёт Ядра), ярлык `NeuroBridge_Диспетчер.lnk`.
- `_Core\Docs\`: единые законы ИИ (`CORE_RULES.md`), стиль (`CORE_STYLE_UI.md`), архитектура ядра (`CORE_ARCHITECTURE.md`), терминология (`CORE_TERMINOLOGY.md`), база ошибок (`CORE_ERRORS.md`) и журнал ядра (`CORE_CHANGELOG.md`).
- `_Core\Runner\`: мультипроектный конвейер (`projects.json`, `watcher_go.ps1`, `hotkey_go.ps1`, `go.ps1`, `auto_footer.ps1`, `snapshot_knowledge.ps1`, `log_chat.ps1`, `progress_ui.ps1`, `runner_log.ps1`, `runner_actions.log`, `_sounds\`, `_launcher_golden\`).
- `_Core\TrayApp\`: исходники диспетчера (`NeuroBridgeTray.csproj`, `Program.cs`) и портативный бинарник `App\NeuroBridgeTray.exe` (выбор проекта, `+` создание, синхронизация, `Экспорт...` в `_Backups\`, тумблеры конвейера).
- `Projects\<id>\`: изолированные проекты со своим отчётом (`<id>_отчёт.txt`), документацией `02_Docs\` и изолированными журналами диалогов (`02_Docs\DIALOG_LOG.md`, `02_Docs\_dialog_history\`).
- `_Backups\`: полные резервные копии проектов и архивы экспорта `NeuroBridge_Export_*.zip`.
## 2. ПРОТОКОЛ НАЧАЛА НОВОГО ДИАЛОГА (3 ОБЯЗАТЕЛЬНЫХ ШАГА)
- Шаг 1 (при получении `старт_нового_чата.txt`): строго запрещено начинать задачи по проекту; ИИ подтверждает знание ядра, называет последний активный проект и спрашивает — продолжаем его или переключаемся на другой проект из списка.
- Шаг 2 (после подтверждения/выбора проекта пользователем): ИИ переводит `active` в `projects.json` (если выбран другой) и первым делом запрашивает в read-only скрипте ВСЮ документацию этого проекта (`02_Docs\DOC_*.md`, `_mod_docs\*.md`, `CHANGELOG_DEV.md`) и хвост истории диалогов (`02_Docs\DIALOG_LOG.md`).
- Шаг 3 (после получения `<id>_отчёт.txt` с полной документацией и историей): ИИ уточняет, на чём именно остановились в этом проекте, и приступает к работе.


- **Прямая адресация отчётов входящим скриптом (go.ps1 через dot-sourcing . $tmp)**: переключение целевого файла отчёта выполняется самим входящим скриптом через переменную $out (NeuroBridge_отчёт.txt, VS_отчёт.txt, Protocol_отчёт.txt). Диспетчер проектов (projects.json -> active) больше не используется для переключения вывода и не изменяется скриптами; go.ps1 исполняет скрипт через . $tmp, считывает его $out и помещает именно этот файл в буфер обмена.


## 3. ПРОТОКОЛ РАЗБОРА ОШИБОК ПРОЕКТОВ
- Любой сбой в прикладном проекте обрабатывается строго по 4-шаговому циклу: Пауза задачи -> Регистрация [В РАБОТЕ] и check_error_class.ps1 в NeuroBridge_Core -> Фикс и подтверждение в <id>_отчёт.txt проекта -> Закрытие [ЗАКРЫТО] в CORE_ERRORS.md до продолжения основной работы.

## 4. УСТРОЙСТВО КОНВЕЙЕРА И РАЗВЯЗКА С ОКНОМ ДИСПЕТЧЕРА
- **Неприкосновенность выбора пользователя в Диспетчере (`projects.json -> active`)**: поле `active` в `projects.json` принадлежит исключительно окну Диспетчера (`NeuroBridgeTray.exe`). Скрипты ИИ **никогда** не перезаписывают `projects.json -> active` при служебных обращениях к Ядру или другим проектам — благодаря этому окно Диспетчера не мигает, не меняет кнопки и не сбивает выбор пользователя.
- **Адресация отчётов по переменной `$out` (`go.ps1`)**: каждый скрипт задаёт свой целевой файл `$out` (`C:\NeuroBridge\NeuroBridge_отчёт.txt` для Ядра или `C:\NeuroBridge\Projects\VS_Mods\VS_отчёт.txt` для проекта). Раннер `go.ps1` после выполнения `step.ps1` читает `$out`, автоматически определяет имя проекта по `report` в `projects.json` для плашки и кладёт именно `$out` в буфер обмена (`SetFileDropList`).
- **Цепочка конвейера (`_Core\Runner\`)**: `watcher_go.ps1` (монитор буфера с AST-проверкой `Test-Ok` каждые 350 мс) или `hotkey_go.ps1` (глобальный хоткей `Alt+E` через `RegisterHotKey`) -> запускают `go.ps1` -> `go.ps1` проверяет антидубль `last_step.hash`, захватывает мьютекс `Global\NeuroBridge_Go_Lock`, пишет `step.ps1` в UTF-8 BOM, исполняет его, кладёт `$out` в буфер и вызывает `auto_footer.ps1` -> `auto_footer.ps1` дописывает `CORE ERROR MONITOR` + всю документацию Ядра (`CORE_*.md`) и вызывает `snapshot_knowledge.ps1` для обновления `старт_нового_чата.txt`.



- **Эталонная многопоточность по проектам (Global\NeuroBridge_Go_Lock_<id> + step_<id>.ps1 + Global\NeuroBridge_Snap_Lock + Global\NeuroBridge_Slot_Lock)**: каждый проект работает в изолированном канале; UI-слоты (slot_<N>_<PID>.lock) бронируются атомарно через Global\NeuroBridge_Slot_Lock со стекированием без наложений, запись старт_нового_чата.txt синхронизируется через Global\NeuroBridge_Snap_Lock, а буфер обмена — через Global\NeuroBridge_Clip_Lock.



- **Единый прогресс-бар запуска (go.ps1 + progress_ui.ps1)**: промежуточная карточка 'Выполняется скрипт...' заменена на единое окно прогресса в UI-слоте потока (автоматический Marquee при старте с бесшовным переходом в точные проценты и ETA при вызове New-ProgressWindow/Update-ProgressWindow внутри скрипта).



- **Регламент фиксации эталона конвейера (_launcher_golden\)**: любое обновление эталонной версии конвейера выполняется строго после прохождения целевого тестирования и прямого подтверждения пользователя, с обязательной записью пути слепка и состава изменений в CORE_ARCHITECTURE.md и CORE_CHANGELOG.md.

- **Удержание активного контура в диалоге**: после переключения на любой проект (включая NeuroBridge_Core) диалог и все последующие шаги удерживаются строго в рамках этого проекта до явного разрешения пользователя на переход в другой проект.

- **Актуальный эталон конвейера и Диспетчера**: зафиксирован в C:\NeuroBridge\_Core\Runner\_launcher_golden\golden_ETHALON_20261125_211200 (UI-сервер NeuroBridge_UI_Pipe, FIFO-очередь queue_<chanId>, порог блоков <=22 строк / <=1800 симв., строгий латинский фильтр создания проектов, автоочистка списка при DropDown, тихий перезапуск --silent, универсальный экспорт на Рабочий стол и дизайн-стандарт окон в CORE_STYLE_UI.md).

- **FIFO-очередь блоков внутри канала (queue_<chanId>\) и тумблер звука (sound.disabled)**: при быстром последовательном копировании блоков одного проекта go.ps1 ставит их в персональную FIFO-очередь канала без ошибки занятости линии, а воспроизведение звуков конвейера управляется кнопкой 🔊/🔇 в Диспетчере (sound.disabled).




- **Канонический генератор нового проекта (CreateProjConfirm в NeuroBridgeTray.exe)**: принимает строго латинские названия проектов (фильтр new_err_latin), полную RU/EN локализацию окна создания (new_title, new_create, ошибки), автоматически разворачивает папку 02_Docs с базовыми файлами (DOC_PROJECT_RULES.md со ссылкой на _Core/Docs и $out, DOC_PROJECT_RUNTIME.md, DOC_PROJECT_ARCHIVE.md, PROJECT_ERRORS.md, DIALOG_LOG.md) и сразу генерирует стартовый <slug>_отчёт.txt через auto_footer.ps1.

- **Автоочистка при раскрытии списка (cbProj.DropDown) и тихий перезапуск (--silent)**: при раскрытии списка проектов Диспетчер удаляет из projects.json проекты с удалёнными папками; служебный перезапуск после сборки запускается с --silent прямо в трей без всплытия и мигания окна.



- **Универсальный мастер экспорта (DoExportZip в NeuroBridgeTray.exe)**: локализованная кнопка <- Назад, фоновая полная упаковка всей среды (включая все бэкапы _Backups, _launcher_golden, _asset_backups и backups) + выбранных проектов на Рабочий стол без автооткрытия Проводника, с живой прогресс-карточкой (проценты, ETA) и финальной зелёной плашкой ShowUiToast (task_ok.wav).





- **Привязка структуры _Core\ к публичному релизу (NB_Protocol)**: стандартные папки Ядра (_Core\Docs\CORE_*.md, _Core\Runner\*.ps1 без step*/g_step*, _Core\Runner\_sounds\*, _Core\TrayApp\Program.cs + App\*) автоматически входят в белый список uild_public_release.ps1. Создание новых подпапок внутри _Core\ запрещено без одновременного обновления белого списка в Projects\NB_Protocol\03_Tools\build_public_release.ps1 и DOC_PROJECT_RULES.md.
